Effect HTTP API provides a schema-first, type-safe approach to building HTTP APIs
in TypeScript.

**Schema-first** means you define the shape of the data an endpoint accepts and
returns before implementing its handler. A **handler** is the function that runs
when a request matches an endpoint. It contains the endpoint's business logic or
calls services that implement that logic.

These schemas, together with the endpoint's HTTP method and path, form its API
contract. The contract describes request parameters, successful responses, and
expected errors.

If you're a TypeScript developer looking to build HTTP APIs with Effect, start
with the [Quickstart](/quickstart) to build your first API, then explore the
[Guides](/guides/handle-query-parameters) to learn more about Effect HTTP API's
features and capabilities.

## How Effect HTTP API works

Effect HTTP API uses the following building blocks:

| Concept | Responsibility |
|---|---|
| `HttpApiEndpoint` | Defines an endpoint's method, path, and request and response schemas. |
| `HttpApiGroup` | Organizes related endpoints into named groups. |
| `HttpApi` | Combines groups into the top-level API contract. |
| `HttpApiBuilder` | Connects endpoints to their handlers and registers API routes. |
| `Layer` | Provides dependencies and manages the resources needed to run the API. |

You first define the API contract, then implement its handlers and provide the
services needed to run the server.

When a request arrives, Effect HTTP API decodes and validates the request data,
passes the typed values to the matching handler, and encodes the result using the
response schema.
