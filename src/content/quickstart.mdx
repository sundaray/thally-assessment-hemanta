In this quickstart, you'll build a `GET /products` endpoint that retrieves a list
of products from [DummyJSON](https://dummyjson.com/docs/products), a free REST API
that provides realistic sample data.

## Before you begin

This quickstart assumes you're familiar with TypeScript and Effect fundamentals,
including Effect Schema and Effect HTTP Client.

You'll need the following tools:

- [Node.js](https://nodejs.org/en/download) 22.19.0 or newer.
- [pnpm](https://pnpm.io/installation) 11.3.0 or newer.
- `curl` to test the endpoint.

The examples use `effect` and `@effect/platform-node` version `4.0.5`.

## 1. Create the project

Run the following commands in your terminal:

```bash
mkdir effect-http-api
cd effect-http-api
pnpm init
pnpm add -E effect@4.0.5 @effect/platform-node@4.0.5
pnpm add -D typescript tsx @types/node@22
pnpm pkg set type=module "scripts.dev=tsx watch server.ts" "scripts.check=tsc --noEmit"
pnpm exec tsc --init --strict --module nodenext --target es2022 --types node
```

The `pnpm pkg set` command updates `package.json` to use ES modules and adds the
`dev` and `check` scripts. The `tsc --init` command creates `tsconfig.json` with
strict type checking. The `tsx` tool runs your TypeScript server and automatically
restarts it when you change the source files.

`@effect/platform-node` provides the Node.js implementation of Effect's HTTP
server.

## 2. Define the API contract

Create `api.ts` in the project root and add the following code:

```typescript title="api.ts"
import { Schema } from "effect";
import { HttpApi, HttpApiEndpoint, HttpApiGroup } from "effect/http-api";

export const productSchema = Schema.Struct({
  id: Schema.Number,
  title: Schema.String,
  description: Schema.String,
  price: Schema.Number,
  category: Schema.String,
  brand: Schema.optionalKey(Schema.String),
});

export const productListSchema = Schema.Struct({
  products: Schema.Array(productSchema),
  total: Schema.Number,
  skip: Schema.Number,
  limit: Schema.Number,
});

export class ProductsFetchError extends Schema.TaggedError<ProductsFetchError>()(
  "ProductsFetchError",
  { message: Schema.String },
  { httpApiStatus: 503 },
) {}

export class ProductsInvalidResponseError extends Schema.TaggedError<ProductsInvalidResponseError>()(
  "ProductsInvalidResponseError",
  { message: Schema.String },
  { httpApiStatus: 502 },
) {}

const productsEndpoint = HttpApiEndpoint.get("getProducts", "/products", {
  success: productListSchema,
  error: [ProductsFetchError, ProductsInvalidResponseError],
});

const productsGroup = HttpApiGroup.make("products").add(productsEndpoint);

export const ecomApi = HttpApi.make("ecomApi").add(productsGroup);
```

The code above defines the contract for `GET /products`. Let's walk through its
four main parts.

### Define the response schemas

We use Effect Schema to define the structure of the product list returned by
`GET /products`. The `productSchema` describes each product, while
`productListSchema` describes the complete response, including the products array
and pagination fields.

Some products returned by DummyJSON don't have a `brand` field, so we use
`Schema.optionalKey` to make it optional.
DummyJSON also returns additional product fields that we haven't included in
`productSchema`. Effect Schema removes these extra fields during decoding, so our
API returns only the fields we've defined.

### Define the error schemas

We define two errors using `Schema.TaggedError`:

- `ProductsFetchError` represents HTTP client failures, such as network errors and
  unsuccessful upstream responses.
  It returns `503 Service Unavailable`.
- `ProductsInvalidResponseError` represents a response that doesn't match our
  schema. It returns `502 Bad Gateway`.

The `httpApiStatus` annotation specifies the HTTP status code for each error.

### Define the endpoint

We define the `GET /products` endpoint using `HttpApiEndpoint.get()`. The function
accepts three arguments:

1. **Identifier:** A unique name for the endpoint (`"getProducts"`).
2. **Path:** The URL path that the endpoint handles (`"/products"`).
3. **Options:** An object specifying the schemas for successful responses
   (`success`) and errors (`error`).

By default, Effect HTTP API returns `200 OK` for a successful response unless you
specify another status code.

### Register the endpoint with the API

We use `HttpApiGroup.make("products")` to create a group and add the `getProducts`
endpoint to it. Then, we use `HttpApi.make("ecomApi")` to create the top-level API
and register the group.

So far, we've only defined the API contract. We haven't implemented the logic
that handles incoming requests. Let's do that next.

## 3. Implement the handler and start the server

Create `server.ts` in the project root and add the following code:

```typescript title="server.ts"
import { NodeHttpServer, NodeRuntime } from "@effect/platform-node";
import { Effect, Layer } from "effect";
import {
  FetchHttpClient,
  HttpClient,
  HttpClientResponse,
  HttpRouter,
} from "effect/http";
import { HttpApiBuilder } from "effect/http-api";
import { createServer } from "node:http";

import {
  ecomApi,
  productListSchema,
  ProductsFetchError,
  ProductsInvalidResponseError,
} from "./api.js";

const productsGroupLayer = HttpApiBuilder.group(
  ecomApi,
  "products",
  (handlers) =>
    Effect.gen(function* () {
      const client = (yield* HttpClient.HttpClient).pipe(
        HttpClient.filterStatusOk,
      );

      return handlers.handle("getProducts", () =>
        client.get("https://dummyjson.com/products").pipe(
          Effect.flatMap(HttpClientResponse.schemaBodyJson(productListSchema)),
          Effect.catchTags({
            SchemaError: () =>
              Effect.fail(
                new ProductsInvalidResponseError({
                  message:
                    "DummyJSON returned an unexpected products response.",
                }),
              ),
            HttpClientError: () =>
              Effect.fail(
                new ProductsFetchError({
                  message:
                    "Unable to retrieve products. Please try again later.",
                }),
              ),
          }),
        ),
      );
    }),
).pipe(Layer.provide(FetchHttpClient.layer));

const ecomApiLayer = HttpApiBuilder.layer(ecomApi).pipe(
  Layer.provide(productsGroupLayer),
);

const httpServerLayer = HttpRouter.serve(ecomApiLayer).pipe(
  Layer.provide(NodeHttpServer.layer(createServer, { port: 3000 })),
);

Layer.launch(httpServerLayer).pipe(NodeRuntime.runMain);
```

The code above implements the `getProducts` endpoint, provides its dependencies,
and starts the HTTP server. Let's look at each part.

### Connect the endpoint to its handler

We use `HttpApiBuilder.group()` to implement the `products` group. It accepts
three arguments:

1. **API:** The top-level API definition (`ecomApi`).
2. **Group name:** The name of the group to implement (`"products"`).
3. **Handler builder:** A function that receives a `handlers` object and returns
   an `Effect` that registers the endpoint handlers.

Inside the function, we use `handlers.handle()` to associate the `getProducts`
endpoint with its implementation.

The handler sends a request to DummyJSON using `HttpClient`. We use
`HttpClient.filterStatusOk` to reject non-successful HTTP responses and
`HttpClientResponse.schemaBodyJson` to parse and validate the response against
`productListSchema`.

If either operation fails, `Effect.catchTags` maps the failure to
`ProductsFetchError` or `ProductsInvalidResponseError`.

Finally, `Layer.provide(FetchHttpClient.layer)` supplies the HTTP client that the
handler needs.

### Assemble the API layer

`HttpApiBuilder.layer(ecomApi)` creates a layer for the API that requires
implementations for its endpoint groups.

We use `Layer.provide(productsGroupLayer)` to supply the implementation of the
`products` group.

### Configure the HTTP server

`HttpRouter.serve(ecomApiLayer)` creates a layer that serves the API's routes
through an HTTP server.

This layer requires an HTTP server implementation. We provide one using
`NodeHttpServer.layer(createServer, { port: 3000 })`, which configures a Node.js
HTTP server to listen on port `3000`.

### Start the server

`Layer.launch(httpServerLayer)` creates an Effect that starts the server and
keeps it running.

`NodeRuntime.runMain` executes the Effect and handles graceful shutdown when you
press `Ctrl+C`.

Now, check your code for TypeScript errors:

```bash
pnpm check
```

Then start the development server:

```bash
pnpm dev
```

You should see a message indicating that the server is listening on port `3000`.
Keep this terminal running while you test the endpoint.

## 4. Test the endpoint

Open a second terminal and run the following command:

```bash
curl -i http://localhost:3000/products
```

You should see `200 OK` and a JSON response containing `products`, `total`, `skip`,
and `limit`.

By default, DummyJSON returns 30 products in the `products` array. For example,
the array includes the following object:

```json
{
  "id": 16,
  "title": "Apple",
  "description": "Fresh and crisp apples, perfect for snacking or incorporating into various recipes.",
  "price": 1.99,
  "category": "groceries"
}
```

Congratulations! You've built and tested your first endpoint with Effect HTTP API.
